# Data Generation Strategy: IC Extension Management

To fulfill the requirement of 5,000+ records and ensure a robust database for performance testing, the following strategy will be used.

## 1. Tools and Approach
- **Tool**: PostgreSQL `generate_series()` function.
- **Dialect**: Standard SQL where possible, using PostgreSQL extensions only for synthetic data generation as permitted by the tech stack for "Data Generation" purposes.

## 2. Table-Specific Strategy

### 2.1 Auxiliary Tables (Manual/Small Scale)
- **TB_INSTRUTOR**: 50 records.
- **TB_PARCEIRO**: 20 records.
- **TB_PROJETO_EXTENSAO**: 10 records.
- **TB_ATIVIDADE**: 100 records (linked to projects).

### 2.2 Core Data (Massive Scale)
- **TB_PARTICIPANTE**: 5,500 records.
  - Names: Generated by concatenating strings (e.g., 'Participant ' || id).
  - Emails: 'user' || id || '@example.com'.
  - Types: Randomized between 'ALUNO', 'COMUNIDADE', 'SERVIDOR'.

### 2.3 Relationships (Massive Scale)
- **RL_INSCRICAO_HISTORICO**: 10,000+ records.
  - Each participant will be enrolled in 1 to 3 activities randomly.
  - Presence: 80% 'PRESENTE', 20% 'AUSENTE'.
  - Grades: Randomized between 0 and 10 using `random()`.

- **RL_ALOCACAO_INSTRUTOR**: 200 records.
  - Each activity will have 1 to 3 instructors.

- **RL_PATROCINIO_EVENTO**: 50 records.

- **RL_MEMBRO_PROJETO**: 300 records.

## 3. Execution Plan
1. Run `schema/ddl_initialization.sql` to ensure clean schema.
2. Run `schema/dml_population.sql` which will contain the `generate_series` logic.
3. Verify counts using `COUNT(*)` queries.
