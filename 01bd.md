### [cite_start]1. Introdução [cite: 7]
[cite_start]*(individual ou grupo de até 5 pessoas)* [cite: 8]

[cite_start]Esta atividade tem a intencionalidade de provocar discentes a explorar os aspectos de projeto, implantação, otimização, suporte e análise de bancos de dados. [cite: 9] [cite_start]No percurso da avaliação se observarão a criatividade, descoberta, rigor, eficiência e capacidade de planejamento na resolução de um problema que mimetiza a complexidade de cenários reais na indústria, mercado e pesquisa. [cite: 10]

[cite_start]O ponto de partida para a condução do projeto é o refinamento de um desafio fictício atribuído pelo professor. [cite: 11] [cite_start]O texto inicial oferecido pelo professor busca emular uma complexidade suficiente para uma exploração completa dos itens avaliados em cada entrega. [cite: 12] [cite_start]A partir disso, cada discente, individualmente, deve refletir sobre os requisitos, elaborar novos requisitos e especificar o minimundo de banco de dados. [cite: 13] [cite_start]Os produtos entregues devem refletir o planejamento, implantação, operação, otimização e administração do banco de dados, observando os requisitos. [cite: 14] 

[cite_start]Todas as demais entregas serão avaliadas a partir de sua coerência com esta delimitação do minimundo, sua modelagem inicial e os documentos de governança. [cite: 15] [cite_start]Adicionalmente, é importante que estes documentos também materializem as demandas do projeto lógico/conceitual. [cite: 16]

Este projeto é organizado em torno de duas avaliações. [cite_start]Cada avaliação se refere a um marco de entrega. [cite: 17] [cite_start]A primeira entrega abriga os desenvolvimentos, descobertas e definições da concepção e implantação do projeto de sistema de informação. [cite: 18] [cite_start]Neste processo, cada discente deve incorporar as melhores práticas de modelagem, cumprindo com as determinações dos artefatos de Governança de Dados. [cite: 19] [cite_start]Estes artefatos descrevem, principalmente, a Metodologia de Administração de Dados (MAD). [cite: 20] 

[cite_start]Seguindo a definição do DATASUS, o MAD contém a regulamentação e descrição que estabelecem padrões e procedimentos a serem adotados quando necessária a realização de tarefas relativas à área de Administração de Dados, considerando o contexto da Governança de Dados. [cite: 21] [cite_start]Parte substantiva desta metodologia é suportada pela ISO/IEC 11179-5:2015, principalmente no seu capítulo orientando estratégias de nomenclatura. [cite: 22] [cite_start]Desta forma, todas as abstrações, relações, restrições e implementações desta entrega devem estar associadas aos requisitos básicos e estendidos do caso atribuído ao discente. [cite: 23, 30] 

[cite_start]O sucesso nesta entrega está diretamente relacionado à capacidade de produzir uma modelagem adequada, uma estratégia de tradução entre modelos (Entidade-Relacionamento para o Relacional) amparados nos fundamentos teóricos oferecidos nos livros-texto da disciplina e, também, no uso efetivo dos mecanismos de otimização do modelo físico. [cite: 30]

[cite_start]As entregas do Marco 2 são compostas pelos avanços na elaboração de rotinas para otimização dos processos de administração do banco de dados pelo sistema de informação e pelos seus atores (Administradores de Bancos de Dados, Analistas de Dados, Gestores, etc.). [cite: 31] [cite_start]Estão compreendidos nesta entrega um conjunto de queries de manipulação de dados, as visões materializadas, stored procedures, transações e otimização de consultas. [cite: 32] [cite_start]Um aprofundamento teórico-prático dos conceitos de bancos de dados e exploração de seus subsistemas para cumprimento dos requisitos previamente estabelecidos é a chave para uma entrega de excelência. [cite: 33] 

[cite_start]No momento da segunda entrega, será possível revisitar a modelagem feita nas entregas do Marco 1. Este exercício de melhoria é de suma importância para garantir que os ajustes provocados pelo feedback do Marco 1 permitam o cumprimento pleno de requisitos e acesso a escalas mais altas de avaliação. [cite: 34]

### [cite_start]2. Marco 1: Elaboração, modelagem e implantação ótima do banco de dados (MIBD) [cite: 36]

#### 2.1. [cite_start]Descritivo das entregas [cite: 37]
[cite_start]A partir do estudo de caso atribuído pelo professor e dos documentos de governança oferecidos, cada grupo deve propor uma extensão do estudo de caso, modelar o banco de dados, implantar o banco de dados usando o modelo relacional no SGBD PostgreSQL, popular as relações no SGBD e otimizar o modelo físico relacional. [cite: 38]

* [cite_start]**Propor uma extensão ao estudo de caso:** Cada discente deverá analisar criticamente o estudo de caso atribuído e propor uma extensão de sua descrição e requisitos que devem ser cumpridos. [cite: 39] [cite_start]Adicionalmente, de maneira justificada, o discente deve especificar um minimundo que inclua as tabelas, relacionamentos e restrições suficientes para cumprir com todos os requisitos. [cite: 40]
* [cite_start]**Modelar o banco de dados:** Cada discente deve, a partir da descrição do projeto, seu minimundo e requisitos, elaborar uma modelagem conceitual e lógica usando o Modelo de Entidade-Relacionamento (MER). [cite: 41] [cite_start]A modelagem deve seguir a notação de Peter Chen, descrita no principal livro-texto da disciplina. [cite: 42]
* [cite_start]**Implantar o banco de dados:** Utilizando o PostgreSQL, discentes devem escrever scripts SQL-DDL (data definition language) para materializar a modelagem MER num banco de dados físico. [cite: 43]
* [cite_start]**Popular o banco de dados:** Para garantir uma avaliação adequada das restrições e do impacto de eventuais otimizações, cada discente deve popular seu banco com um volume de dados sintéticos. [cite: 48]
* [cite_start]**Otimizar o modelo físico relacional:** Cada discente deverá elaborar planos de indexação, justificados de acordo com os requisitos e a natureza das tabelas propostas. [cite: 49] [cite_start]Para cumprir com a avaliação de desempenho, o discente deve criar 10 (dez) consultas de complexidade intermediária e outras 10 (dez) avançadas. [cite: 50]

#### [cite_start]Relatório de entrega: [cite: 51]
[cite_start]O relatório da Entrega 1 deve seguir o modelo de Capítulo de Livros da SBC (Sociedade Brasileira de Computação). [cite: 52] [cite_start]Seu conteúdo deve estar organizado em, pelo menos cinco seções, como descrito no Quadro 1. [cite: 53]

[cite_start]**Regras:** [cite: 61]
* [cite_start]Discentes podem usar apenas SQL ANSII para operar no banco de dados, sendo proibido o uso de conexão remota ao SGBD através de outras linguagens de propósito geral (Python, R, Java, Julia, C, etc). [cite: 62]
* [cite_start]Os anexos devem estar organizados para permitir que a correção aconteça sem erros. [cite: 63] [cite_start]Discentes podem optar por incluir links externos ou documentos auxiliares. * [cite_start]Consultas intermediárias envolvem no mínimo 3 tabelas E devem utilizar pelo menos 2 das seguintes funções: JOIN, GROUP BY, WINDOW e COUNT. [cite: 68]
* [cite_start]Consultas avançadas envolvem no mínimo 3 tabelas E devem utilizar pelo menos 3 das seguintes funções: SUB-CONSULTAS, JOIN, GROUP BY, WINDOW e COUNT. [cite: 69]
* [cite_start]Todas as consultas devem estar associadas a pelo menos um requisito, isso deve estar explícito no relatório. [cite: 70]
